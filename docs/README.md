V3 targets English authoring, UI, and export. Translated-webnovel, wuxia, and xianxia register or terminology may be optional style support; Chinese authoring is not a product requirement. V2 remains a separate repository at `D:\WebnovelStudio_V2`, and V3 does not read or write V2 author data at runtime. Broader author-trial integration and full persistence/reconciliation qualification, import, providers, durable Apply, and reviewed-story behavior remain later gates. Context documentation distinguishes stored evidence, permitted available sources, the packet actually delivered, and model-understood behavior that still requires evaluation; it does not authorize paid autosave analysis, automatic canon, or replacement of source text with a huge summary.

The default native UI now provides a persistent Library/Workspace with blank projects, optional document types, Rust SQLite autosave, flush-before-switch, rename, duplicate, archive/unarchive, and native folder/backup/recovery/TXT dialogs. W1 structural scope validation and shared JS/Rust fixtures are implemented; W2 session/core receipts and reconciliation are implemented; current schema-6 storage includes durable pre-upgrade/recovery handling and guidance tables, while registry/transfer work remains active. The explicit W0 sample editor remains session-only, and persistent UI qualification is still open. The context implementation is core plus the W4 discussion surface: C1 retains original source and restricts aliases to private AuthorRoom until safe grants; C2 preserves exact request inputs, validates all resolved source material, persists inspectable packet receipts through restart, and exposes them over native IPC; W4 persists discussions, selected scope quotations, drafts, deterministic mock output, and context inspector state without mutating manuscript bodies. C3 persists author-confirmed guidance from chat or direct entry as immutable versions at Next request, This document, or This project scope; frozen guidance is mandatory and separately typed in AuthorRoom packets, has distinct receipt handles, and is visible in the inspector. Restricted writing excludes all current guidance. New preparation is blocked after story edits, stale packets remain inspectable, and policy revocation blocks old reads. Relevant permitted history compilation, linked retry guidance reuse, persistent chapter/project source pins, safe briefs, durable Apply, C4–C6, live providers, and packaged/native accessibility qualification remain open.
