# WebnovelStudio V3 product requirements

**Status:** confirmed product direction; the native development app has persistent projects, mock discussions, C3 author guidance, selected-passage Apply/Reject, saved-version restore, and exact Markdown/TXT export previews. Windows installer configuration is present. Full author trials, installed-release qualification, live assistance, and later story features remain open, 5 September 2026.

WebnovelStudio helps an author manage several webnovel projects, develop story material in any order, write chapters, and revise them through discussion. It should feel like a writing application with an assistant.

- **Installed desktop:** a native application window with native menus/dialogs and an installer. Rust owns the core and the web UI runs inside Tauri. An externally opened browser does not satisfy this requirement.
- **Project management:** creating, opening, finding, renaming, duplicating, archiving, switching, and resuming projects are central flows. Samples are explicitly chosen; a blank project remains useful without a model connection.
- **Free creative order:** an author may begin with a world, protagonist, theme, hook, scene, chapter, or ordinary note. These are optional entry points, not required stages.
- **Writing first:** the manuscript is central. Plain language, familiar editing, persistent position, and recoverable saves take precedence over exposing backend workflow stages.
- **Whole-chapter feedback:** a chapter can have a persistent chat. Feedback is requested explicitly; creating or saving a chapter does not start a paid critique.
- **Selected feedback:** words, sentences, paragraphs, and larger selections can be discussed through a toolbar, context menu, and keyboard alternative. The UI shows the captured quotation and the possible edit scope.
- **Author control:** an explicit edit request produces a reviewable suggestion. Apply changes the manuscript; Reject leaves it unchanged. Discussion is not canon and never silently authorizes a whole-chapter rewrite.
- **Local ownership:** manual writing works offline; projects are portable and recoverable. A working manuscript is distinct from revisions, accepted story records, and export history.
- **Explicit model choice:** recognizable model names and supported traits remain visible. Settings own credentials and configuration. There is no silent provider or model substitution.
- **Honest context:** the product distinguishes evidence stored in the project, permitted sources available for lookup, the packet actually delivered to a model, and what the model appears to understand (an evaluation question). Context maintenance does not run paid analysis on autosave, automatically write canon, or replace source text with a large rolling summary.
- **Language and genre:** English is the authoring, UI, and export language. Translated-webnovel, wuxia, and xianxia register or terminology may be optional style support; Chinese authoring is not a product requirement, and no genre's stages, chapter lengths, or schedule are mandatory.

## Current native surface

The default native UI opens a persistent Library/Workspace with blank projects and optional chapter, character, world, theme, hook, scene, and note documents. It wires autosave through Rust-owned SQLite, flush-before-switch, project/document rename, duplicate, archive/unarchive, and native folder, backup, recovery, and export dialogs. W1 structural scope validation and shared JS/Rust fixtures are implemented; W2 session/core receipts and reconciliation are implemented. Current schema 9 includes guidance, durable discussion retry selection, proposals, and immutable export records, alongside exact-head caret/last-document state, metadata compare-and-swap, and `context_source_epoch`. Recovered copies have isolated identities and operation namespaces; copied historical snapshots, proposals, and receipts cannot authorize new project operations.

The Story Context core currently has C0's pure contracts and 16 adversarial tests plus C1's working-basis Rust snapshot/retrieval actor. C1 retains original source, performs exact literal/lexical scans and source-only alias matches, returns Unicode UTF-16 spans, tracks revocation and source staleness conservatively, retries snapshots across restart, and rebuilds a disposable per-document index with yielding. C2's Rust pure deterministic compiler validates source bodies, descriptors, projections, eligibility, and scope; preserves exact target, instruction, scope, and mandatory pins; uses full eligible text when it fits and stable whole-block prefix packing with explicit omissions otherwise; and persists exact packet messages, options, and hashes through native IPC. W4 and C3 provide persistent author-room discussions, bounded recent exchanges, selected scopes, guidance, deterministic mock responses, and context inspection. This W5 checkpoint adds explicit Discuss/ProposeEdits intent, restricted chapter-passage requests with a reader frontier, deterministic three-alternative output, immutable candidates/prepared versions/decisions, exact replacement validation, and a Rust-owned single-author Apply/Reject path. Restricted edit packets exclude author-room private/future material, guidance, and recent chat. Apply atomically records the new body, source epoch, before/after revisions, decision, and receipt; stale proposals remain reviewable but cannot apply. The development Apply contracts are covered by [CI run 33981203728](https://github.com/FZWINGEL/WebnovelStudio_V3/actions/runs/33981203728); installed-release and broader native/release qualification remain separate. The current W6 development slice adds saved-version comparison and explicit document restore; see the [document history contract](docs/ADR_0005_DOCUMENT_HISTORY.md). Persistent chapter/project source pins, safe briefs, whole-chapter/block/manual-rebind/batch proposal Apply, C4–C6, and live-provider qualification remain open.

Export draft shows the exact frozen Markdown or plain-text file, its saved version, and formatting limitations before opening a native Save dialog. The operation writes a new file and records its source revision, format, bytes, and hash. Later writing does not change an already prepared preview. See the [draft export contract](docs/ADR_0006_DRAFT_EXPORT.md). This does not establish reviewed-story readiness or publication approval.

The V2 Codex adapter/model-picker remains an authorized reference for integration and actual LLM requests. [Codex qualification](docs/CODEX_QUALIFICATION.md) records native 0.153.3 discovery and bounded synthetic experiments; production discussions remain mock-only and provider support is still unqualified. See [proposal and Apply contract](docs/ADR_0004_PROPOSAL_APPLY.md) for the precise local boundary.

## Explicit W0 trial

The trial action and its validation IPC are available only in development builds. Installed release builds open the persistent Library without a session-only trial entry point.

The implemented W0 surface is a native Tauri/WebView2 editor trial. It opens a built-in sample chapter, supports paragraph and heading styles, bold and italic marks, links, scene breaks, clipboard text/formatting notice, undo/redo, whole-chapter or selected-passage feedback notes, replacement preview/reject, a local replacement transaction, and Rust snapshot validation over IPC. The editor stays mounted while feedback state changes, and stale captured selections are refused after intervening edits.

The trial is not a product release or the persistent author-data path. Its sample text and feedback are session-only and disappear when the window closes. The W0 trial itself does not connect a provider or AI response, and its snapshot command does not persist the sample. The remaining English native author trial, minimum-window behavior, external Word paste, screen-reader use, broader native qualification, live providers, and installed-package qualification remain future gates. Unicode edge cases such as accents, emoji, and names are internal robustness fixtures, not a Chinese authoring feature. See the [W0 qualification record](docs/W0_QUALIFICATION.md) for executed evidence.

V3 lives in `D:\WebnovelStudio_V3`, alongside V2. Windows is the first qualification target; other operating systems, collaboration, cloud sync, V2 import, and reviewed-story features remain separately gated. The design documents describe intended contracts; they do not establish native editing quality, provider reliability, continuity coverage, or literary quality.
